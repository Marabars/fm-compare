# FM Compare — сравнение версий финансовых моделей

**Версия:** 0.1.0 · **Язык интерфейса:** русский · **Платформа:** Windows · **Режим работы:** полностью офлайн.

Инструмент для аудита и анализа изменений между двумя версиями финансовой Excel-модели (или между двумя листами одного файла). Не передаёт данные за пределы рабочей станции — все вычисления выполняются локально.

---

## Возможности

- Сравнение **двух файлов** Excel (V1 vs V2) по выбранным листам.
- Сравнение **листов внутри одного файла** с явным сопоставлением пар (например, `BS_2025 ↔ BS_2026`).
- Два режима глубины анализа:
  - **Full audit trail** — полный аудит: значения, формулы, скрытые строки, комментарии, сдвиги периодов.
  - **Quick KPI Check** — быстрая проверка только ключевых KPI.
- Двухфазная валидация KPI: пользователь подтверждает найденные программой адреса ячеек и единицы измерения перед запуском полного сравнения.
- Inline-редактирование адресов и единиц измерения KPI в диалоге проверки + экспорт/импорт через Excel.
- Excel-отчёт: Executive Summary, KPI Comparison, Top Changes, Business Diff, Formula Changes, Timing Shifts, Warnings, Run Settings, использованный словарь.
- Настраиваемый порог материальности (абсолютный и/или процентный).
- Редактируемый бизнес-словарь KPI и листов.

## Требования

- **Windows** (тестировалось на Windows Server 2022 и Windows 10/11).
- **Python 3.8+** (рекомендуется 3.11+).
- Установленные пакеты:
  - `openpyxl`
  - `tkinter` (входит в стандартную поставку Python для Windows).


## Запуск

Из корня проекта:

```powershell
python main.py
```

При первом запуске создаётся каталог `%APPDATA%\FM_Compare\` для логов и пользовательских настроек.

## Пошаговая инструкция

### 1. Выбор файлов

В блоке **«Файлы»** выберите Excel-файлы кнопкой **Обзор…**:

- **V1** — базовая (исходная) версия модели.
- **V2** — новая версия, с которой сравниваем.

Поддерживаются форматы `.xlsx` и `.xlsm`. Файлы свыше 30 МБ помечаются предупреждением.

### 2. Режим «один файл» (сравнение листов внутри одного файла)

Если нужно сравнить два набора листов внутри одной книги (например, прошлогодний и текущий BS/PL):

1. Выберите файл в строке **V1**.
2. Поставьте галочку **«Сравнить листы внутри одного файла (V2 = V1)»**.
3. Строка V2 будет автоматически отключена.
4. После нажатия **Запустить сравнение** откроется диалог **«Сопоставление листов: V1 ↔ V2»**: добавьте нужные пары листов (например, `(BS_2025, BS_2026)`, `(PL_2025, PL_2026)`).
5. Дальше процесс идентичен обычному сравнению.

⚠ В отчёте и в диалогах KPI адреса V2 отображаются с именем парного V1-листа — это нормально, так удобнее сравнивать строки.

### 3. Выбор листов

Кнопки **«Листы V1…»** и **«Листы V2…»** открывают список листов рабочей книги. По умолчанию выбраны все листы из словаря. Снимайте/ставьте галочки, чтобы исключить нерелевантные листы (служебные, скрытые расчёты, и т.п.).

### 4. Выбор режима

В блоке **«Режим»**:

- **Полный аудит (Full Audit Trail)** — детальный анализ. Используйте для финального аудита.
- **Быстрая проверка KPI (Quick KPI Check)** — только ключевые KPI, без формул и сдвигов. Используйте, когда нужен быстрый снэпшот.

### 5. Порог материальности

Кнопка **«Изменить…»** рядом с порогом или меню **Файл → Настройки**:

- **Абсолютный порог (руб.)** — изменения меньше N считаются несущественными.
- **Процентный порог (%)** — изменения меньше N% считаются несущественными.
- Если оба не заданы, существенными считаются **все** изменения.

### 6. Запуск сравнения

Нажмите **▶ Запустить сравнение**. Процесс идёт в два этапа:

#### Фаза 1 — проверка KPI

Программа сканирует файлы, находит адреса каждого KPI и единицы измерения. Открывается диалог **«Проверка адресов и единиц измерения KPI»**:

- Колонки **Ячейка V1 / V2** и **Ед. изм. V1 / V2** доступны для редактирования двойным щелчком.
- Можно экспортировать таблицу в Excel (**Экспорт в Excel**), отредактировать офлайн и **Загрузить** обратно.
- Цветовая разметка строк: зелёный — найдено автоматически, жёлтый — не найдено, синий — отредактировано вручную.

Нажмите **«Подтвердить и сравнить»** для запуска Фазы 2, или **Отмена** для прерывания.

#### Фаза 2 — полное сравнение

Программа загружает файлы целиком и формирует все результаты. Прогресс отображается в статусной строке внизу окна.

### 7. Результаты

После завершения откроются вкладки:

- **Сводка** — Executive Summary с группировкой по KPI и Top-X крупнейших изменений.
- **KPI** — таблица всех KPI с V1, V2, Δ, Δ%, impact, адресами ячеек.
- **Business Diff** — все различия по бизнес-ключам с типом сопоставления, материальностью, изменением знака.
- **Изменения формул** — что поменялось в формулах ключевых листов, в том числе формулы с изменённой логикой при том же значении.
- **Timing Shifts** — обнаруженные сдвиги по периодам (например, выручка из Q3 переехала в Q4).
- **Предупреждения** — несопоставленные строки, отсутствующие листы, пункты для ручной проверки.

### 8. Экспорт отчёта

Кнопка **«Сохранить отчёт…»** открывает диалог сохранения. Имя файла предлагается автоматически (`Model_Comparison_Full_YYYY-MM-DD_HHMM.xlsx`). Отчёт пишется атомарно — частично записанный файл не остаётся при сбое. После сохранения программа предложит открыть его.

## Настройки

**Файл → Настройки**:

- **Материальность** — абсолютный и процентный пороги.
- **Top-X изменений** — сколько крупнейших изменений показывать в сводке (5–50, по умолчанию 10).
- **Включить изменения комментариев** / **скрытых строк** — добавляет соответствующие листы в отчёт.
- **Debug-логирование** — расширенное логирование (только технические координаты, без бизнес-данных).
- **Директория вывода** — где по умолчанию открывается диалог сохранения отчёта.

Настройки хранятся в `%APPDATA%\FM_Compare\settings.json`.

---

## Бизнес-словарь

**Инструменты → Бизнес-словарь…** — редактор словаря KPI и листов:

- **KPI** — название, группа, уровень (1 = руководитель, 2 = аналитик), единица измерения, направление улучшения (рост/падение/нейтрально).
- **Листы** — паттерны имён листов, групповая принадлежность, флаг ключевого листа.

Словарь хранится в `%APPDATA%\FM_Compare\dictionary.json`. Можно экспортировать в Excel, отредактировать офлайн и импортировать обратно.

При обновлении словаря старые отчёты пересчитывать не нужно — новый словарь применится при следующем запуске сравнения.

## Безопасность и приватность

- **Полностью офлайн** — никаких сетевых запросов, телеметрии, отправки данных.
- **Безопасный логгер** — в логи попадают только технические события (имя операции, кол-во строк, время, тип ошибки). Бизнес-данные (значения ячеек, формулы, имена контрагентов, содержимое строк, пути файлов) **не логируются**.
- **Финансовые данные** не покидают доверенный контур.
- Логи: `%APPDATA%\FM_Compare\logs\fm_compare_YYYYMMDD.log`.

## Известные ограничения

- Только `.xlsx` / `.xlsm`. Старый формат `.xls` не поддерживается.
- Файлы со скрытыми/сложными именованными диапазонами VBA не анализируются.
- Поддержка внешних ссылок (`[external.xlsx]Sheet1!A1`) ограничена — будут предупреждения.
- В режиме «один файл» rename действует только в памяти; исходный файл не изменяется.
- Сравнение работает на машинах с тяжёлыми моделями (>50 МБ) медленно — рекомендуется заранее снять с листов «лишние» данные или ограничить выбор листов.

## История изменений

### v0.1.0 (текущая)
- **Сравнение внутри одного файла** — новый режим с явным парованием листов через отдельный диалог; engine принимает `sheet_rename_v2` mapping.
- **Двухфазная валидация KPI** — отдельный диалог проверки адресов ячеек и единиц измерения перед полным сравнением.
- **Inline-редактирование** в диалоге KPI: адреса и единицы измерения (`Ед. изм. V1 / V2`).
- **Экспорт/импорт KPI-резолюций** через Excel для офлайн-редактирования.
- **Цветовые подсказки** строк KPI: найдено / не найдено / отредактировано вручную.
- **Адреса ячеек** показываются в KPI, Business Diff, Timing Shifts, Warnings.
- **Атомарная запись отчёта** с поддержкой UNC-путей.
- Исправления: формат единиц измерения в сводке (нет двойного префикса `тыс.`), KPI row matching по best match, корректная обработка `EmptyCell` в openpyxl read-only.
